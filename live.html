How it works

Every night at 10pm ET a GitHub Action runs nightly_orders.py. The script reads the AMZN prices and positions that Sanji writes to this repo, pulls this week's AMZN option chain from LSEG, decides what the wheel should do next, and writes the result to open_orders.json in the repo root (plus a copy in mkt/, where the order spec says Sanji reads). Sanji fills the orders against the next session's prices and updates the positions, and the next night's run starts from that new book.

The rules

Book (from positions.json)First session of the week?Order written
Cash onlyYesSell 1 AMZN put, this week's expiry, strike nearest 30-delta
100+ sharesYesSell 1 covered call per 100 shares, this week's expiry, strike nearest 30-delta
Short put or call still openAnyNothing
AnythingNoNothing

These are the same rules and parameters as my backtest. Assignment is not an order: Sanji applies it at the close. Until Sanji publishes a positions file, the script assumes the book is cash. Every order is checked against the Sanji spec before it is written, and if LSEG or the positions file can't be read, the run stops without writing anything.

Choosing the strike

  

    
Sanji's delta:30 strike and mid price tokens can't be resolved yet, so the script works
       out the contract itself and writes an exact expiry, strike and limit price:

    
    
      
  1. Take the last listed AMZN expiry in the week of the order (normally Friday).
    2. 
      
  2. Get each option's bid and ask at the prior close from LSEG and take the mid.
    3. 
      
  3. Solve Black-Scholes for the implied vol that matches the mid (r = 3.75%, time from the quote date).
    4. 
      
  4. Recompute delta and price with time measured from the order date, as the backtest did.
    5. 
      
  5. Sell the out-of-the-money strike with |delta| closest to 0.30, with the limit at that model price.
    6. 
    

    
A sell limit fills at the open whenever the open is above it, so the limit acts as a floor: normally the
       option is sold at Monday's opening price.

Why this strategy

  
  

    Okay so, I chose this strategy first of all because the token i shared with the professor was from my wheel repo. I believe the wheel is ideal since every decision depends on what i already hold. With the cash we sell a put, after assignment we sell calls, and while the option is open we wait. This all fits well with how Sanji is designed. I kept my strategy from the wheel intact, since i had already worked through the parameters and reasoning.

Reflection

  
  

    Sanji doesn’t fill orders yet, so there is no live P&L, and the script treats the book as cash until a positions file appears. Let's wait and see what happens. The strike is also picked from Friday’s close, so a weekend gap can move it away from 30-delta. To improve I would ideally I would use Sanji's delta, so the strike is picked based on MOnday's open, and skip weeks that have earnings calls like we saw in the last backtest.
